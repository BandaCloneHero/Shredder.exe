CONTEXTO DO SHREDDER.EXE
- Frontend HTML/JavaScript sem bundler; backend Node.js/Express/Socket.IO.
- Homologação isolada no GitHub Codespaces, com porta 3001 privada e acesso HTTPS pelo encaminhamento app.github.dev.
- Firebase projectId: shredder-d22a2; authDomain: shredder-d22a2.firebaseapp.com.
- O domínio temporário foi adicionado aos domínios autorizados. Google foi habilitado no Firebase Console, conforme informado pelo responsável.
- Web SDK oficial via CDN www.gstatic.com/firebasejs, versão configurada 12.19.0.
- initializeAuth com inMemoryPersistence e browserPopupRedirectResolver; GoogleAuthProvider com prompt: select_account; signInWithPopup disparado diretamente pelo clique.
- A preparação do SDK termina com sucesso. O popup efetivamente abre, conforme observado pelo responsável. Ainda não sabemos em qual ponto dentro do fluxo Google a operação é rejeitada.
- A promessa de signInWithPopup é rejeitada como FirebaseError com código textual fora da lista estática local. O diagnóstico mostra AUTHENTICATION_FAILED CODE_NOT_ALLOWLISTED TYPE_FirebaseError.
- Não se chega ao getIdToken(true) nem ao POST /validate do receptor nesta sequência. O código original foi descartado pela filtragem, portanto não está disponível para comparação.
- Não há vínculo automático por e-mail, cadastro local ou emissão de sessão Shredder nesse teste.
- O receptor independente utilizará Firebase Admin SDK, ADC por representação de conta de serviço e verifyIdToken(token, true), com checagens adicionais de projeto, provedor e autenticação recente. A leitura ADC já foi comprovada em um teste anterior. Isso não comprova o fluxo Web.
- Não queremos substituir a sessão local existente por uma sessão Firebase nem implementar créditos/pagamentos nesta etapa.
